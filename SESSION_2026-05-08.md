# Session Notes — 2026-05-08

Continuation of the production deployment of the Orlanda RAG platform to the Ubuntu server (185.237.220.6) at `platform.n8norlanda.com`. This session focused on post-deploy fixes: admin rights, Monday OAuth, missing dependencies, and Anthropic tool-schema compatibility.

## 1. Admin Rights for Registered User

**Problem:** User registered with `armann@orlanda.info` got `role="user"` instead of `admin`.

**Root cause:** `config.py` stored `ADMIN_USERNAMES = {"armann@orlanda.info"}` (full email), but `auth.py._register_db()` checks against the *canonical* username (`_canonical_username()` strips `@domain` → just `armann`). So `"armann" in {"armann@orlanda.info"}` → `False`.

**Quick fix on server (no code change needed):**

```bash
docker exec -it platform-postgres psql -U platform -d platform \
  -c "UPDATE users SET role='admin' WHERE username='armann';"
```

Effective immediately on next login.

## 2. Monday OAuth Redirect URI

**Problem:** After clicking "Connect monday" and authorizing, the browser was redirected to `http://192.168.0.205:8000/auth/monday/callback` (local dev IP) instead of the production domain.

**Cause chain:**
1. `RAG_MONDAY_OAUTH_REDIRECT_URI` in `.env` still pointed at the local LAN IP from when it was tested locally.
2. `docker compose restart` does **not** re-read `.env` — it only restarts the process inside an existing container. Env vars are baked in at container *creation* time.
3. The `.env` file ended up with two conflicting `RAG_MONDAY_OAUTH_REDIRECT_URI` lines (old + appended new) and the appended line had the wrong callback path (`/monday/oauth/callback` instead of `/auth/monday/callback`).

**Fix on server:**

```bash
# Remove all old redirect lines and add the correct one
sed -i '/RAG_MONDAY_OAUTH_REDIRECT_URI/d' /opt/platform/.env
echo 'RAG_MONDAY_OAUTH_REDIRECT_URI=https://platform.n8norlanda.com/auth/monday/callback' >> /opt/platform/.env

# Recreate (NOT restart) the container to pick up new env
cd /opt/platform && docker compose up -d --force-recreate platform

# Verify
docker exec platform env | grep MONDAY_OAUTH_REDIRECT
```

**Also required:** add `https://platform.n8norlanda.com/auth/monday/callback` to the allowed redirect URLs in the Monday Developer Center for the OAuth app.

**Key learning:** `docker compose restart` ≠ `docker compose up -d --force-recreate`. For env-var changes, always use the latter.

## 3. Monday Tools Not Being Called

**Problem:** After connecting Monday successfully, asking Monday-related questions produced generic answers — the agent never invoked any Monday MCP tools.

**Root cause:** `langchain-mcp-adapters` was installed in the local dev venv but not listed in `requirements.txt`, so the production Docker image didn't have it. `monday_auth.py.get_monday_mcp_tools_for_user()` catches `ImportError` silently, logs a warning, and returns `[]` — so the agent ran with zero Monday tools.

**Fix in `requirements.txt`:**

```diff
 slowapi>=0.1.9
 python-multipart
+langchain-mcp-adapters
```

On server (without git):

```bash
echo 'langchain-mcp-adapters' >> /opt/platform/requirements.txt
docker compose build platform
docker compose up -d --force-recreate platform
```

Also confirmed `RAG_ENABLE_MONDAY_MCP=true` in `.env`.

## 4. Anthropic 400: `For 'number' type, properties maximum, minimum are not supported`

**Problem:** Once Monday tools loaded, Claude rejected requests with:
```
anthropic.BadRequestError: Error code: 400 - tools.1.custom: For 'number' type, properties maximum, minimum are not supported
```

Monday MCP tools include JSON Schema constraints (`minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf`) on number/integer fields. These are valid JSON Schema, but Anthropic's tool API explicitly rejects them.

**Why "it worked locally":** Likely a different installed version of `langchain-mcp-adapters` (not pinned in requirements), or the Monday MCP server returned a different tool set. Either way, the deployed image hit the constraint.

### Attempts that didn't work

1. **Monkey-patch `args_schema.model_json_schema` via `type.__setattr__`** — Pydantic v2's `ModelMetaclass` rejected the write; the surrounding `try/except: pass` swallowed the error silently and tools shipped with constraints intact.
2. **Subclass `args_schema` with overridden `model_json_schema`** — LangChain's `BaseTool.tool_call_schema` property internally calls `_create_subset_model(...)`, which builds a *fresh* Pydantic model from the original `model_fields`. The subclass override was discarded.
3. **Strip `FieldInfo.metadata` and rebuild via `create_model`** — Pydantic v2 caches the core schema at class creation, so post-creation FieldInfo mutation didn't change `model_json_schema()` output even after `model_rebuild(force=True)`.
4. **Patch `_create_subset_model` to post-process the result** — Same caching problem; mutating fields on the returned class didn't affect schema generation.

The earlier patch attempts also broke startup once because `_create_subset_model`'s real signature accepts `descriptions`/`fn_description` keyword arguments and our wrapper rejected them.

### What worked

Patch the **final tool-converter** in `langchain_anthropic` so we mutate the exact dict that becomes the JSON request body. This bypasses every Pydantic schema-caching layer because we're modifying the output, not the class.

Added to the top of `rag_agent/monday_auth.py` (runs at module import time):

```python
def _patch_anthropic_tool_converter() -> None:
    import copy as _copy

    _STRIP_KEYS = ("minimum", "maximum", "exclusiveMinimum",
                   "exclusiveMaximum", "multipleOf")

    def _strip(obj):
        if isinstance(obj, dict):
            if obj.get("type") in ("number", "integer"):
                for k in _STRIP_KEYS:
                    obj.pop(k, None)
            for v in list(obj.values()):
                _strip(v)
        elif isinstance(obj, list):
            for item in obj:
                _strip(item)
        return obj

    def _wrap(module, attr_name):
        original = getattr(module, attr_name, None)
        if original is None or getattr(original, "_anthropic_strip_patched", False):
            return False
        def _patched(*args, **kwargs):
            result = original(*args, **kwargs)
            if isinstance(result, dict):
                cleaned = _copy.deepcopy(result)
                _strip(cleaned)
                return cleaned
            return result
        _patched._anthropic_strip_patched = True
        setattr(module, attr_name, _patched)
        return True

    # Patch convert_to_anthropic_tool wherever langchain-anthropic exposes it
    # (chat_models, package root, _client) plus the openai converter as backup.
    ...

_patch_anthropic_tool_converter()
```

The full implementation patches `convert_to_anthropic_tool` in three possible module locations (different langchain-anthropic versions expose it from different paths) and `convert_to_openai_tool` as a safety net.

**Verify after deploy:**

```bash

```

Should print:
```
Patched langchain tool converters to strip Anthropic-incompatible number constraints
```

## 6. Deploy Commands Reference

For any future code change that touches `.env` or Python source:

```bash
cd /opt/platform
git pull                                        # pull latest source
docker compose build platform                   # rebuild image (only needed for code/deps)
docker compose up -d --force-recreate platform  # NEW container picks up new env + image
docker logs platform --tail 50                  # verify startup
```

For *only* a Python source change (no new deps): the rebuild step pulls in the new code via `COPY . .` in the Dockerfile, then `--force-recreate` swaps the container.

For *only* an `.env` change: skip the build, just `--force-recreate`.

`docker compose restart` is not equivalent and will silently keep the old environment.

## 7. Operational Notes for Future Debugging

- **Admin role mismatch** — `ADMIN_USERNAMES` is compared against the canonicalised username (local part only). If you list a full email there, registrations of that email won't auto-promote. Either (a) list the local part in the env var, (b) update the row in the `users` table, or (c) fix the comparison in `config.py` to canonicalise on load.
- **MCP tool schemas + Anthropic** — Any future MCP server we wire in could produce the same `minimum`/`maximum` 400 if its tools constrain numbers. The patch in `monday_auth.py` is global (it patches langchain-anthropic, not just Monday tools) so it should cover other MCP integrations too.
- **Container restart vs recreate** — Burned us twice this session. Default to `--force-recreate` whenever env or image changes.
- **Silent error handlers** — Several bugs were masked by `except Exception: pass` (the missing `langchain-mcp-adapters` import, the failed `type.__setattr__` patch). When something is "configured but not working", grep for silent excepts in the relevant code path first.
